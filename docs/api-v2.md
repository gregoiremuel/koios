# API v2 de Koîos : parcours (formation par niveaux ou sans fin), paliers recoupés par 2 IA, images, quiz

S'ajoute à l'API existante (docs/api.md) ; les routes V1 et V1.1 restent en place. Même style : `functions/api/<route>.js`, ajout dans `worker.js`, JSON, erreurs `{erreur}` en français, quotas par jour UTC, cache D1 partagé entre tous les lecteurs (un contenu n'est rédigé qu'une fois).

## Fournisseurs (secrets Cloudflare, jamais dans le dépôt)

- Rédaction, dans l'ordre : Gemini, Cerebras, Groq, Mistral (API), GLM, Grok, Llama (Workers AI) ; un fournisseur sans clé est ignoré (sans aucune clé : Llama, repli Mistral). Un échec (429, 5xx, délai, réponse illisible) passe au suivant sans casser la génération.
  - `gemini` (`env.GEMINI_API_KEY`, secret Cloudflare) : `POST https://generativelanguage.googleapis.com/v1beta/models/<modèle>:generateContent`, clé dans l'en-tête `x-goog-api-key` (jamais dans l'adresse). Modèles essayés dans l'ordre : `gemini-2.5-flash`, `gemini-2.0-flash`, `gemini-flash-latest` (400, 403, 404 ou 429 -> suivant ; le modèle qui répond est retenu), ou `env.GEMINI_MODELE`. Messages convertis : `system` -> `systemInstruction`, `assistant` -> `model`. `generationConfig` : `maxOutputTokens`, `temperature`, `responseMimeType: application/json`, et `thinkingConfig.thinkingBudget: 0` (série 2.5 flash). La sortie est ramenée à la forme chat.completions.
  - `cerebras` (`env.CEREBRAS_API_KEY`, `https://api.cerebras.ai/v1/chat/completions`, modèles `gpt-oss-120b`, `llama-3.3-70b`, `qwen-3-32b`), `groq` (`env.GROQ_API_KEY`, `https://api.groq.com/openai/v1/chat/completions`, `llama-3.3-70b-versatile`, `openai/gpt-oss-120b`, `qwen/qwen3-32b`) et `mistral` (`env.MISTRAL_API_KEY`, API officielle `https://api.mistral.ai/v1/chat/completions`, `mistral-medium-latest`, `mistral-small-latest`) : compatibles OpenAI, actifs seulement si le secret existe, chacun sa famille et sa mémoire PAR MODÈLE. 429 -> modèle suivant et modèle écarté 10 min (3 h si « par jour ») ; 404 ou 400 « modèle inconnu » -> écarté 24 h ; 401 ou 403 -> famille ignorée 1 h ; `response_format: json_object` envoyé, repli sans lui si 400 (retenu). Gemini : cascade `gemini-3-flash-preview`, `gemini-2.5-flash`, `gemini-flash-latest`, `gemini-flash-lite-latest`, `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`, `gemini-2.5-flash-lite`, `gemini-2.0-flash`, `gemini-2.0-flash-lite`.
  - `glm` (`env.GLM_API_KEY`) : API compatible OpenAI, `POST https://api.z.ai/api/paas/v4/chat/completions`, modèle `env.GLM_MODELE` ou `glm-4.7-flash` (puis les autres couples z.ai / open.bigmodel.cn), `Authorization: Bearer <clé>`.
  - `grok` (`env.GROK_API_KEY`, préfixe `grok_…`, service d'origine incertain) : API compatible OpenAI, couples essayés dans l'ordre `https://api.x.ai/v1/chat/completions` (`grok-3-mini`, `grok-4-fast`) puis `https://api.groq.com/openai/v1/chat/completions` (`llama-3.3-70b-versatile`) ; 400, 401, 403 ou 404 -> couple suivant ; le couple qui répond est retenu. Imposable par `env.GROK_MODELE` (et `env.GROK_URL`).
  - Workers AI : `@cf/meta/llama-3.3-70b-instruct-fp8-fast` (Llama), `@cf/mistralai/mistral-small-3.1-24b-instruct` (Mistral). Délai d'un appel : 60 s au plus.
- Vérification : toujours une autre famille que la rédaction, dans l'ordre Cerebras, Groq, Mistral (API), Gemini, GLM, Grok, puis Workers AI (Mistral, Llama), moins la famille du rédacteur (les deux modèles de Workers AI se vérifient en dernier recours : Mistral vérifie Llama). Champ `verification.ia` = noms des deux modèles.
- Quota épuisé : un 429, ou l'erreur Workers AI « 4006 : you have used up your daily free allocation of 10,000 neurons », met le fournisseur de côté pour 10 minutes (mémoire de l'isolat) : plus d'essai à chaque leçon, puis nouvel essai. Si tous sont de côté, la chaîne complète est réessayée. Les erreurs 502 distinguent les causes : « quota gratuit de GLM épuisé ; Workers AI épuisé », « délai dépassé », « réponse illisible ».
- `claude` (`env.CLAUDE_API_KEY`, modèle `claude-haiku-5-5`) : actif seulement si le secret existe ; premier pour la rédaction, avant gemini ; jamais vérificateur de lui-même (la vérification part de Gemini, puis cerebras, groq, mistral, glm, grok, Workers AI). `claudeCle` dans le diagnostic.
- Leçons : extraits Wikipédia (FR, puis EN si le français a moins de 2 000 caractères) en cache 30 jours (table `sources_cache`), donnés au rédacteur et au vérificateur. Vérification à 3 verdicts (`vrai`, `faux` + correction, `incertain`), 700 jetons. Plus de 20 % de phrases retirées ou corrigées, ou une section de base (`enBref`, `comment`, `pourquoi`) vide : réécriture une fois, sinon publiée `verification.aRevoir`. Un seul modèle rédige les parties A et B. Admin : `POST /api/admin {action: 'reecrire', parcours}`.
- Secrets : `GEMINI_API_KEY`, `CEREBRAS_API_KEY`, `GROQ_API_KEY`, `MISTRAL_API_KEY`, `GLM_API_KEY`, `GROK_API_KEY`, `DIAG_KEY` (jamais dans le dépôt). `GET /api/diagnostic?cle=<DIAG_KEY>` (404 sans la bonne clé) essaie gemini, cerebras, groq, mistral, glm, grok, llama et mistral (Workers AI) avec une question minuscule : état, durée, extrait, `quota: "épuisé"` si besoin, et `couple` = `{url, modele}` qui a répondu (tous sauf Workers AI) ; `cerebrasCle`, `groqCle`, `mistralCle` (présence des clés) et `modelesCompat` (état de chaque modèle). Aucune clé n'apparaît dans la réponse.
- Images : Unsplash si `env.UNSPLASH_KEY` (`GET https://api.unsplash.com/search/photos?query=<q>&per_page=3&orientation=landscape&content_filter=high`, en-tête `Authorization: Client-ID <clé>` ; crédit avec liens `?utm_source=koios&utm_medium=referral`), sinon l'image de la page Wikipédia, gardée seulement si sa fiche Commons (`titles=File:<nom>`, imageinfo/extmetadata) donne auteur et licence libre : `credit` = auteur · licence · « Wikimédia Commons », `lien` = page du fichier. Pexels n'est plus utilisé. Commons et Unsplash sont les seules sources de photos. Requête d'image en anglais (champ `motImage`). Commons écarte les images générées par une IA (`-hastemplate:"PD-algorithm"` et mention « AI-generated » ou « PD-algorithm » dans Categories ou ImageDescription).
- Sources : Wikipédia FR et EN (recherche + extrait, comme lib/wiki.js ; 6 000 caractères au plus par langue), plus les pages de référence citées. `User-Agent: Koios/2.0 (https://koios.gregoire-muel.workers.dev)`.

## Tables (ajout)

- `parcours(id TEXT PRIMARY KEY, titre TEXT, contenu TEXT, auteur TEXT, vues INTEGER DEFAULT 0, cree TEXT)` : `contenu` = `{ resume, image, motImage, etapes, sources, programme }`.
  - **Formation par niveaux** (parcours créés depuis le lot 1 du plan v3) : `programme = { niveaux: [{ numero, titre, modules: [{ numero, titre, objectif }] }] }`. 4 niveaux (Bases, Intermédiaire, Avancé, Expert, dans cet ordre ; titres libres de 3 à 40 caractères), Bases : 6 à 10 modules ; Intermédiaire, Avancé, Expert : 5 à 10 chacun (21 à 40 modules en tout). Chaque module : titre 3 à 60 caractères, objectif 20 à 160, `prerequis` (0 à 3 titres de modules précédents ; un titre inconnu est retiré sans rejet). Aucun titre en double. Bases part de zéro : « Qu’est-ce que <sujet> ? », vocabulaire, grands repères, puis une notion par module. Les modules sont numérotés de 1 à M dans l'ordre des niveaux. `etapes` = les modules déjà ouverts : étape n = module n, `{ numero, titre (= titre du module), niveau (numéro), objectif, paliers: [{ numero, titre }] }`. Un module compte 6 à 10 leçons (= paliers), une idée par leçon. Les niveaux ajoutés par « Aller plus loin » s'appellent « Maîtrise n » (3 à 5 modules). La numérotation des paliers est globale : les numéros d'un module continuent après le dernier palier des modules ouverts.
  - **Ancien format** (sans `programme`) : `etapes: [{ numero, titre, paliers }]` de 10 paliers, sans fin. Comportement inchangé.
- `paliers(id TEXT PRIMARY KEY, parcours TEXT, numero INTEGER, contenu TEXT, vues INTEGER DEFAULT 0, cree TEXT)`, index sur `parcours`.
- `quiz_direct(parcours TEXT PRIMARY KEY, contenu TEXT, cree TEXT)`.
- `variantes(id TEXT PRIMARY KEY, contenu TEXT, cree TEXT)` : id = `parcours:n:mode` (mode `simple` ou `expert`).

Identifiants : parcours `slug(titre)` (40 caractères au plus, `[a-z0-9-]`) ; palier `<parcours>:<numero>`.

## Routes

1. `POST parcours { titre }` (auth) : renvoie l'existant sans rien générer ; sinon quota 10/jour/lecteur et 80/jour au total (un parcours compte pour 1), puis : sources ; appel 1 = programme d'ensemble (`{ resume (2 phrases), motImage (anglais), niveaux: [{ titre, modules: [{ titre, objectif }] }] }`, 50 s au plus, 7000 jetons ; le niveau Bases part de zéro) ; appel 2 = liste de 5 à 10 titres de leçons du module 1 (30 s au plus, le programme complet est fourni pour situer) ; image de tête. Même chronomètre de 85 s pour l'ensemble. Erreurs : 422 « Je ne trouve aucune source fiable sur ce sujet. Essaie une autre formulation. » ; 502 « Le Rival n’a pas réussi à écrire ce parcours. Réessaie, ou change la formulation. » (programme ou module 1 invalide, deux IA essayées). → `{ parcours }` = `{ id, titre, resume, image, etapes, sources, programme, modulesTotal }`.
2. `GET parcours?id=` → `{ parcours }` (même forme ; `programme: null` et `modulesTotal: 0` pour l'ancien format ; 404 sinon) ; `GET parcours` → `{ parcours: [{ id, titre, image, vues, paliers }] }`, 60 plus lus (`paliers` = leçons connues).
   - `GET parcours?q=<texte>` (public) : recherche dans les identifiants (titres), sans accents ni casse, tous les mots requis ; 30 résultats triés par vues, `{ id, titre, image, vues, paliers, lecons (écrites), modules, niveaux: [{ numero, titre }] }` ; 400 sous 2 lettres ; une recherche ne compte pas de vue. Une formation qui existe n'est jamais régénérée.
   - `POST parcours { id, prolonger: true }` (auth, « Aller plus loin ») : seulement si tous les modules sont ouverts (409 sinon) ; 400 pour un identifiant invalide ou un ancien format, 404 inconnu, 503 sans IA. Quota 5/jour/lecteur et 40/jour au total (429). L'IA écrit 3 à 5 modules d'un niveau « Maîtrise n » (titres neufs, prérequis existants), ajoutés au programme pour tous (anti-course : le premier enregistré gagne). → `{ parcours }`. 502 si la liste est invalide après repli.
   - `GET fiche?parcours=<id>&de=<k>&a=<k>` (public, sans IA ni quota, 20 leçons au plus) : `{ lecons: [{ numero, titre, aRetenir, definitions }] }` des leçons écrites.
   - Leçon (par niveaux) : champs ajoutés `avant` (0 à 3 rappels), `exemple` (1 à 3 phrases ou null), `cartes` (2 à 4 `{ recto, verso }`) ; sections de 2 à 6 phrases (en bref 2 à 3), 1 à 6 définitions ; 5000 jetons, 85 s au total. Tout passe par la vérification de la 2e IA (carte non confirmée retirée, exemple null, rappel retiré).
3. `GET palier?parcours=<id>&n=<k>` : en cache → `{ palier }` (public). Sinon auth + quota 30/jour/lecteur et 300/jour au total. Si `k` dépasse le plan, génère d'abord le plan de l'étape suivante, l'enregistre dans le parcours (même quota) : ancien format = 10 paliers plus pointus, sans répéter les titres existants ; **formation par niveaux** = les leçons du module suivant (module `etapes.length + 1`, 5 à 10 titres, sans répéter les titres publiés), numéros qui continuent. `k` de 1 à 1500 (PALIER_MAX), au plus 10 au-delà des paliers connus.
   - Erreurs propres à la formation : 404 « Formation terminée : tu as fait le tour de ce sujet. » quand tous les modules sont ouverts et que `k` dépasse le dernier palier (public, sans connexion ni quota) ; 404 « Palier introuvable : lis d’abord les paliers précédents. » si `k` est trop loin, ou si le module ouvert compte moins de leçons que `k` (le module reste enregistré) ; 502 « Le Rival n’a pas réussi à écrire la suite de ce parcours. Réessaie dans un moment. » si la liste de leçons est invalide.
   - **Leçon d'une formation par niveaux** : le prompt reçoit le niveau et sa consigne de ton (Bases : partir de zéro, tout mot technique défini, phrases très simples ; Intermédiaire : relier les notions, causes et enchaînements ; Avancé : cas, nuances, débats ; Expert : sources, controverses, limites des connaissances), le module (titre, objectif, liste de ses leçons) et les noms des termes déjà définis dans les leçons précédentes (40 au plus, à ne pas redéfinir). Champs ajoutés au palier : `niveau` `{ numero, titre }`, `module` `{ numero, titre }`, `aRetenir` (2 à 4 phrases de 15 à 160 caractères, obligatoire), `mnemo` (`null` ou 20 à 200 caractères : moyen mnémotechnique, jamais un fait nouveau). `definitions` : 1 à 5 termes. 4 000 jetons au plus. `aRetenir` et `mnemo` passent par la vérification : un « à retenir » non confirmé est retiré, un `mnemo` non confirmé devient `null`.
   `palier` = `{ id, parcours, numero, etape, titre, image, sections: { enBref, comment, pourquoi, ouQuand }, definitions: [{ terme, definition }], frise: [{ date, evenement }], chiffres: [{ libelle, valeur, unite }], notions: { noeuds, liens }, histoire, questions, sources, verification }`.
   - `sections` : 2 à 4 phrases chacune, en français simple et précis ; une section sans matière vaut `null` (au moins `enBref` et une autre).
   - `definitions` : 2 à 5 termes du palier. `frise` : 0 ou 3 à 6 dates. `chiffres` : 0 ou 3 à 6 valeurs numériques, même unité. `notions` : facultatif (4 à 7 nœuds, 3 à 8 liens). `histoire` : une anecdote ou un fait historique sourcé, ou `null`.
   - `questions` : 4 questions sur ce palier : 2 `{ type: "qcm", enonce, reponses: [4], bonne, explication }`, 1 `{ type: "vraifaux", affirmation, vrai, explication }`, 1 `{ type: "qcm", … }` plus difficile. `explication` : pourquoi la bonne réponse est juste (et pourquoi les autres non), 1 à 3 phrases.
   - `sources` : `[[titre, url]]` des pages réellement utilisées.
   - Vérification : la 2e IA reçoit les extraits et la liste numérotée de toutes les affirmations (phrases des sections, définitions, dates, chiffres, histoire, bonnes réponses et explications) et renvoie `{ "nonConfirmees": [numéros] }`. Ce qui n'est pas confirmé est retiré (une question dont la réponse n'est pas confirmée est retirée). Si plus de 40 % est retiré ou s'il reste moins de 2 questions : une nouvelle rédaction, puis on garde la meilleure. `verification = { ia: [rédacteur, vérificateur], affirmations, retirees, statut: "recoupe" (rien retiré) | "partiel" }`.
4. `GET quiz?parcours=<id>&n=10&graine=<entier>` → `{ questions: [{ palier, titre, index, question }] }` tirées des paliers en cache du parcours, de façon déterministe. S'il y en a moins de 5 : `POST quiz-direct { parcours }` (auth, quota 10/jour/lecteur, mis en cache par parcours) génère 10 questions avec explications à partir des sources du parcours, vérifiées de la même façon → `{ questions }` au même format (`palier: "<id>:quiz"`).
5. Duels : accepter aussi les références `{ chapitre: "<parcours>:<k>", index }` (palier en cache) et `{ chapitre: "<parcours>:quiz", index }`.
6. `PUT progression` : `points` = `etat.xp` borné à 0-1 000 000 (au lieu de la somme des chapitres) ; `valides` = nombre de paliers terminés (`etat.parcours[*].fait`, borné).
7. `GET glossaire?parcours=<id>&jusqua=<k>` (public, sans connexion ni quota) : les mots définis dans les leçons 1 à `k` d'un parcours. Lit seulement le cache (table `paliers`, `numero <= k`) : ne génère rien et ne compte pas de vue. Reprend `definitions` puis `reperes` de chaque leçon (`json_extract` en SQL ; une ligne illisible est écartée par `json_valid`). → `{ termes: [{ terme, definition, numero, titre }] }` : `numero` et `titre` = la première leçon où le terme apparaît ; un terme qui revient (comparé sans accents, sans casse, espaces et apostrophes unifiés) n'est gardé qu'une fois ; tri alphabétique français (`localeCompare('fr', { sensitivity: 'base' })`, puis numéro de leçon). Les dates ne sont pas des mots : un terme qui commence par un chiffre, par « vers » et un chiffre, ou par un nom de mois suivi d'un chiffre (« mars 1889 ») est écarté ; « Mars » seul reste. Parcours bien formé mais inconnu, ou sans leçon en cache : `{ termes: [] }`. 400 si `parcours` manque ou n'est pas un identifiant (`[a-z0-9-]`, 40 au plus), ou si `jusqua` n'est pas un entier de 1 à 1500 (200 termes au plus renvoyés pour une leçon). Les parcours vérifiés (`v-xx`, fichiers statiques) n'ont pas cette route : l'app construit le même glossaire en lisant leurs leçons 1 à `k`.
   - Côté app : onglet « Glossaire » d'une formation (leçons déjà faites, recherche sans accents ni casse) ; dans une leçon `n`, le glossaire des leçons 1 à `n-1` (gardé en mémoire par parcours pour la session) souligne la première occurrence de chaque terme connu et ouvre sa fiche.
8. `GET image?q=<sujet>&source=auto|commons|unsplash` (public, sans connexion) → `{ image }` ; `image = { src, alt, largeur, hauteur, credit, lien, source }` ou `null`. `q` : 2 à 80 caractères (400 sinon) ; `source` : `auto` par défaut (Commons d'abord, Unsplash ensuite), 400 si inconnue.
   - **Commons** (sans clé) : `GET https://commons.wikimedia.org/w/api.php?action=query&generator=search&gsrnamespace=6&gsrsearch=<q> filetype:bitmap&gsrlimit=10&prop=imageinfo&iiprop=url|extmetadata|size|mime&iiurlwidth=1200&format=json`, avec `User-Agent: Koios/2 (https://koios.gregoire-muel.workers.dev)`. Seules les licences libres passent (`LicenseShortName` : domaine public, CC0, CC BY, CC BY-SA ; NC, ND, « fair use » et fichiers non libres écartés), JPEG, PNG ou WebP de 800 px de large au moins. `credit` = auteur (champ `Artist` sans HTML, 80 caractères au plus) · licence · « Wikimédia Commons » ; un fichier sans auteur n'est gardé que s'il est du domaine public ou CC0. `lien` = page du fichier (`descriptionurl`). `source: "commons"`.
   - **Unsplash** (`env.UNSPLASH_KEY`) : `src` et `credit` hotlinkés, `auteur`, `lienAuteur` et `lienSource` (liens `?utm_source=koios&utm_medium=referral`) ; au choix de la photo, un appel à `links.download_location` (une fois, hors de la réponse, via `waitUntil`) comme l'exigent les règles d'Unsplash. `source: "unsplash"`.
   - Cache : table `images`, clé `<source>:<requête en minuscules>`, y compris l'absence de résultat ; pas de cache quand un fournisseur est en panne (HTTP, réseau, JSON illisible), pour ne pas figer une absence. Quota : 400 recherches nouvelles par jour au total (`image:total`), au-delà `{ image: null }`.
   - Côté app : couverture 16:9 d'une formation (`source=auto`, mot `motImage` si présent), image 3:2 d'une leçon (`source=commons`, requête « titre de la leçon + titre de la formation ») qui ne s'affiche que si elle arrive, vignettes de 48 px et tuiles de l'accueil.

## Test local

`scripts/serveur_local.mjs` simule aussi GLM (fetch vers api.z.ai), Unsplash, Commons (exige le `User-Agent` Koios, renvoie d'abord un fichier non libre et un fichier trop petit, puis un fichier libre) et Wikipédia ; toutes les adresses d'images sont réécrites vers des aplats gris sans texte (`/images-simulees/<n>.svg`), pour une démonstration crédible de bout en bout. `scripts/test_api.mjs` couvre chaque nouvelle route et la vérification (affirmations retirées, nouvelle rédaction, statut), dont le glossaire (vide, tri, dédoublonnage, borne `jusqua`, 400) et les images (licence non libre et petite image écartées, crédit nettoyé du HTML, repli Unsplash, `download_location`, cache par source, absence mise en cache sauf panne, quota).

## Quiz de culture générale, question du jour, salons, tournoi

Tables : `quiz_general(id TEXT PRIMARY KEY, sujet TEXT, bloc INTEGER, contenu TEXT, cree TEXT)` (ids `<slug>:<k>`, `jour:AAAA-MM-JJ`, `tournoi:<lundi>` ; `contenu` = `{ questions, sources, verification }`) et `salons(id TEXT PRIMARY KEY, titre TEXT, type TEXT, fin TEXT, cree TEXT)` (une ligne par salon ou tournoi, `id` = id du duel ; pas de ligne = duel ordinaire). Code : `lib/general.js`, `genererBlocQuiz` dans `lib/paliers.js`. Questions au format de GET quiz : `{ palier: "qg:<slug>:<k>", titre, index (dans le bloc), question }`.

1. `POST quiz-general { sujet, n, regenerer?, apres? }` (auth) : sujet 2 à 80 caractères libres (slug comme les parcours), `n` ∈ 10, 20, 30, 40, 50. Blocs de 10 questions (7 à choix, 3 vrai ou faux, difficulté mêlée) écrits à partir des extraits Wikipédia FR et EN du sujet, vérifiés par la 2e IA (comme `quiz-direct` ; un bloc peut compter 5 à 10 questions). Sans `regenerer` : blocs 1 à n/10. Avec `regenerer: true` : les n/10 blocs qui suivent le bloc `apres` (défaut n/10 ; sans limite, au-delà de 5 des blocs neufs 6, 7…, jusqu'à 9999). **Un seul bloc manquant est écrit par requête** : réponse `{ questions (celles déjà prêtes), manquants, blocs (numéros demandés) }` ; l'app rappelle tant que `manquants > 0`. Un bloc k > 1 reçoit les énoncés déjà écrits pour ce sujet (100 au plus) pour ne pas les répéter. Quota : 25 blocs nouveaux par lecteur et par jour, 150 au total (un bloc en cache ne coûte rien). Erreurs : 400 (sujet, n, regenerer, apres), 401, 422 « Je ne trouve aucune source fiable sur ce sujet. » (avant tout quota), 429, 502, 503.
2. `GET quiz-general?bloc=<slug>:<k> | jour:AAAA-MM-JJ | tournoi:AAAA-MM-JJ` (public) : `{ questions }` d'un bloc en cache ; 404 sinon. Sert à rejouer un salon et à revoir ses erreurs.
3. `GET jour[?date=AAAA-MM-JJ]` (public) : `{ date, theme, question }`. Thème = liste fixe de 60, jour de l'année modulo 60. `date` n'est lue que la veille, le jour ou le lendemain (UTC). Première requête du jour : un bloc de 10 sur le thème, on garde la 1re question à choix (cache `jour:<date>`), sans quota de lecteur, 5 tentatives par jour au total. Échec ou plafond : 200 `{ date, theme: null, question: <pool vérifié via ASSETS ou null>, repli: true }`, jamais d'erreur.
4. Duels : `POST duel` accepte `qg:<slug>:<k>` (le bloc doit exister), `titre` (1 à 60 caractères), `type` (`duel` par défaut : 5 à 20 questions, score obligatoire ; `salon` : 5 à 50 questions, score facultatif), `fin` (date ISO à venir, 31 jours au plus). `GET duel` ajoute `titre, type, fin, termine, joueurs, classement` (`[{ rang, pseudo, justes, n, points, date, moi? }]` trié par points, puis bonnes réponses, puis date). `PUT duel` : 409 après `fin` ; un tournoi ne se joue qu'une fois (409). `GET duels` : aussi les duels créés sans score ; salons et tournois ajoutent `titre, type, fin`. Les joueurs d'un salon sont illimités.
5. `GET tournoi` (public) : `{ tournoi: { id, titre, theme, debut, fin, termine, questions, joueurs, classement (10 premiers), moi, dejaJoue } }` ou `{ tournoi: null }`. Semaine du lundi 00:00 au dimanche 23:59:59 (UTC), thème par semaine ; créé à la première requête (même génération que `jour`, 5 tentatives par jour au total). Le tournoi est un duel de type `tournoi` dont l'id vient du lundi (un seul par semaine, même en cas de requêtes simultanées) ; on le joue avec `GET`/`PUT duel`.

## Formation à plusieurs (groupes) et jeu en direct (parties)

Tables : `groupes(id TEXT PRIMARY KEY (8 car. a-z0-9), nom, parcours, createur, cree)`, `groupe_membres(groupe, joueur, rejoint, PRIMARY KEY(groupe, joueur))`, `parties(id TEXT PRIMARY KEY (6 car.), createur, titre, questions, etat, indice, debut_question, cree)`, `parties_joueurs(partie, joueur, points, PRIMARY KEY(partie, joueur))`, `parties_reponses(partie, joueur, indice, choix, ms, juste, PRIMARY KEY(partie, joueur, indice))`. Code : `lib/groupes.js`, `lib/parties.js`.

### Groupes (`functions/api/groupe.js`)

1. `POST groupe { nom, parcours }` (auth) → `{ id }`. `nom` : 2 à 40 caractères ; `parcours` : identifiant d'une formation du cache D1, ou d'une formation vérifiée (`v-xx`) du catalogue `contenu/parcours.json` (lu via ASSETS). Le créateur est inscrit. Quota : 10 groupes créés par jour et par joueur (429) ; 20 groupes suivis au plus par joueur (409). 404 si la formation n'existe pas.
2. `POST groupe { id, rejoindre: true }` ou `POST groupe?id=…&action=rejoindre` (auth) → `{ ok, id }` (`dejaMembre: true` si déjà dedans, sans rien changer). 12 membres au plus : 409 « Ce groupe est complet ». Le plafond est vérifié dans l'ordre SQL d'écriture (`INSERT … SELECT … WHERE COUNT(*) < 12`), donc sûr même si deux joueurs arrivent ensemble.
3. `POST groupe { id, quitter: true }` ou `?action=quitter` (auth) → `{ ok }`. Le dernier qui part supprime le groupe.
4. `GET groupe?id=` (public) → `{ groupe: { id, nom, parcours, parcoursTitre, createur, max, complet, dejaMembre, membres, classement } }`. `classement` : `[{ rang, pseudo, lecons, xp, activite, moi? }]`, trié par leçons faites, puis XP, puis pseudo ; rang partagé à égalité parfaite. Seuls les pseudos sortent.
5. `GET groupe` (auth) → `{ groupes: [{ id, nom, parcours, membres }] }` : mes groupes (20 au plus, du plus récent au plus ancien).

**Progression : aucune nouvelle écriture.** Le groupe lit `joueurs.etat` (déjà écrit par `PUT progression`) : `etat.parcours[<formation>]` donne `fait` (leçons faites, même lecture que le classement : liste, objet ou nombre, 500 au plus), `xp` (XP gagnée sur la formation) et `date` (dernière activité). La lecture passe par `json_extract` sur ce seul sous-objet ; un état illisible vaut « rien de fait ». Comme l'app envoie sa progression avec un délai de 0,7 s, la page du groupe l'envoie une fois à l'ouverture avant de lire.

### Parties en direct (`functions/api/partie.js`)

Toutes les écritures sont des `POST partie { action, … }` (auth) ; lecture par `GET partie?id=`. Le code se saisit sans tenir compte de la casse.

1. `creer { questions: [{ chapitre, index }], titre? }` → `{ id, code }` (`id` = `code`, 6 caractères parmi `A-H J-N P-Z 2-9` : ni O, ni 0, ni I, ni 1). 5 à 20 références validées comme `POST duel`, mais seulement `<parcours>:<k>` (palier), `<parcours>:quiz` et `qg:<bloc>` (quiz général ou tournoi), et seulement des questions à choix ou vrai ou faux (400 sinon). Quota : 20 parties par jour et par joueur. Les parties de plus de 24 h sont effacées à la création suivante. Le créateur est le premier joueur.
2. `rejoindre { id }` : avant le début seulement (409 « déjà commencé »), 12 joueurs au plus (409 « complète »). Un joueur déjà dedans reste accepté.
3. `demarrer { id }` : créateur seulement (403). La question 1 démarre à l'heure du serveur. 409 si déjà démarrée.
4. `repondre { id, indice, choix }` : `choix` = numéro de la réponse (QCM) ou 0 = Vrai, 1 = Faux. Une seule réponse par question (409). Refusée hors délai : 409 « Trop tard » si la question n'est plus en cours (au-delà de 20 s, ou autre `indice`). 403 si on ne joue pas dans la partie.
5. `GET partie?id=` → `{ partie: { id, code, titre, createur, etat, indice, total, restant, duree, max, joueurs, moi, question? } }`.
   - `etat` : `attente` | `question` | `resultat` | `fini`. `restant` : ms avant la fin de la phase en cours (0 en attente et à la fin). `duree` : 20 000.
   - `joueurs` : pseudos seulement. En attente : `{ pseudo, createur?, moi? }`. Pendant la question : plus `repondu`, sans points. Au résultat et à la fin : `{ rang, pseudo, points, justes, createur?, moi? }`, classé par points (rang partagé à points égaux).
   - `moi` : `{ joueur, createur, repondu?, choix?, juste?, gain? }` ; `juste` et `gain` n'apparaissent qu'au résultat.
   - `question` (joueurs de la partie seulement) : QCM `{ type, enonce, reponses }`, vrai ou faux `{ type, affirmation }`. **Ni la bonne réponse ni l'explication avant `resultat`** ; au résultat s'ajoutent `bonne` (numéro ; 0 = Vrai, 1 = Faux) et `explication`.

**Temps.** Une question dure 20 s, puis 5 s de résultat, puis la suivante démarre toute seule ; après la dernière, `fini`. Aucune tâche de fond : `debut_question` est le début de la question `indice`, et chaque lecture calcule l'état avec l'horloge du serveur (`avancer` dans `lib/parties.js`). Quand l'état calculé diffère de l'état écrit, la lecture l'écrit avec `UPDATE … WHERE etat = ? AND indice = ? AND debut_question = ?` : un seul lecteur gagne, les autres relisent ; le résultat est le même quel que soit l'ordre. L'horloge est `Date.now()`, sauf si `env.maintenant` existe (tests seulement).

**Points.** Juste = 100 + bonus de rapidité de 50 à 0 (linéaire sur 20 s, arrondi) ; faux ou pas de réponse = 0. Le total d'un joueur est recalculé depuis ses réponses (`ms`, `juste`), dans le même lot que l'écriture de la réponse : jamais compté deux fois.

**Limites.** 12 joueurs, mise à jour toutes les 2 secondes (4 s si l'onglet est caché), pas de WebSocket : une lecture fait quelques requêtes D1, donc 12 joueurs coûtent environ 6 lectures par seconde. Pas d'XP gagnée en direct.


## Variantes de lecture (lot 3c) : `POST /api/variante`

Corps `{ parcours, n, mode }`, mode `simple` ou `expert`. Connexion obligatoire (401). 400 : parcours invalide, cours vérifié v-xx, n non entier, mode inconnu. 404 : parcours ou leçon absents. 503 : pas d'IA.
Réécrit `enBref` et les sections d'explication de la leçon en cache, à partir de ses extraits Wikipédia ; vérifié par la 2e IA (phrases non confirmées retirées). Cache dans `variantes` : une version en cache ne coûte ni IA ni quota. Quota : 15 par jour et par lecteur, 150 par jour au total (429). Réponse `{ variante: { id, parcours, n, mode, sections, verification } }`.
